--------------------------------------------------------------------------------
2. ARCHITECTURAL DESIGN & INVARIANTS
--------------------------------------------------------------------------------
- Immutability of CAS Objects:
  CAS objects are identified exclusively by their cryptographic SHA-256 digests
  and written once via atomic temporary file rename (`.tmp` -> `fsync` -> rename).
  Once committed to disk, CAS blobs are completely immutable. Reader threads open
  shared read-only handles (`File::open`) without needing exclusive locks, enabling
  linear read scaling across arbitrary thread or process counts.

- Metadata Handle Scope & Windows Sharing Safety:
  During `CasStorage::get_entry`, the file handle is enclosed strictly within
  deserialization scope, ensuring that the file descriptor is released immediately.
  Concurrent readers updating access timestamps or hit counts operate on atomic
  replacement without locking or blocking other reader threads.

- Isolated Workspace Restoration:
  When multiple runner processes or worker threads execute the same computation
  concurrently, each worker restores output artifacts from immutable CAS blobs
  into its own designated workspace without contending for write locks or corrupting
  shared storage.
