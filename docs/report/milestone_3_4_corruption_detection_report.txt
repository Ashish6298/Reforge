1. OBJECTIVE & REQUIREMENTS:
--------------------------------------------------------------------------------
- Every stored CAS object must be verifiable against its expected cryptographic digest.
- If expected digest != actual digest:
    * Signal a structured `CacheError::IntegrityError`.
    * Never return corrupted / bitrotted bytes as valid cache hits.
    * Automatically quarantine the invalid object (e.g. renaming to `.corrupted`)
      so it can no longer be accessed or restored by computations.
    * Allow the execution engine to fall back to safe re-execution rather than crashing.

2. IMPLEMENTATION DETAILS:
--------------------------------------------------------------------------------
- CAS Verification & Quarantine Logic (`CasStorage::verify_object` in `crates/cache-storage/src/cas.rs`):
    * Computes actual SHA-256 digest from the on-disk file stream via `Digest::from_reader`.
    * Compares expected digest with actual on-disk digest.
    * On mismatch:
        1. Immediately moves/renames the offending file to `path.with_extension("corrupted")`.
        2. Returns `CacheError::IntegrityError { expected, actual, path }`.
- Consumer Safeguards:
    * `CasStorage::get_object_reader(&digest)`: Runs `verify_object(&digest)?` prior to opening a stream.
    * `Storage::get(&digest)`: Inherits pre-read validation and quarantine.
    * `Cache::restore(&entry, dest)`: Verifies all output blobs before writing to disk.
    * `RunnerEngine::execute()`: Catches integrity failure, clears corrupted entry reference,
      quarantines bad blobs, and safely recomputes.
