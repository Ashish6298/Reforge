1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Milestone 18.2 formalizes and verifies end-to-end integration test coverage across
all 7 complete execution flows in the Developer Computation Cache (`dcc`):

  1. Command Miss Flow:
     - Cold execution triggers child process execution.
     - Captures stdout/stderr and exit code.
     - Validates declared required outputs physically exist on disk.
     - Hashes outputs and ingests blobs into CAS (`.dcc_cache/objects/`).
     - Atomically commits `CacheEntry` JSON record with ExecutionStatus::Miss.

  2. Command Hit Flow:
     - Warm execution with identical inputs bypasses process execution (0 ms duration).
     - Cryptographically verifies CAS blobs against expected digests.
     - Atomically restores output files to workspace with verified byte fidelity.
     - Replays captured stdout and stderr streams with ExecutionStatus::Hit.

  3. Input Changed Flow:
     - Modifying any declared input file alters its streaming SHA-256 digest.
     - Canonical key recalculation yields a distinct CacheKey.
     - System executes fresh computation without stale cross-contamination.

  4. Output Missing Flow:
     - Commands exiting with code 0 that fail to produce declared required outputs
       trigger strict validation rejection (`CacheError::MissingOutput`).
     - Caching is rejected to prevent incomplete workspace state.

  5. Cache Corruption Flow:
     - Bitrotted or tampered CAS blobs or corrupted metadata entries are detected
       via cryptographic checksum validation.
     - Corrupted files are automatically quarantined (`*.corrupted`).
     - System gracefully falls back to re-computation without failing the build.

  6. Concurrent Access Flow:
     - Multiple concurrent workers simultaneously requesting the same cold key are
       coordinated via advisory `ComputationLock`.
     - Exactly 1 worker executes the computation while remaining workers wait on the
       lock, re-check the cache, and receive instant 0 ms warm hits.

  7. Failed Command Flow:
     - Commands exiting with non-zero exit codes (`exit 1` or `exit 42`) capture error
       diagnostics but are never cached by default (`DO NOT CACHE` policy).
     - Subsequent runs re-execute cleanly.
