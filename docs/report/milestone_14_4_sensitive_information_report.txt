1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Milestone 14.4 addresses accidental caching and leakages of sensitive information
(such as passwords, security tokens, API keys, private keys, database connection
strings, and credentials) into cache entries, CAS blobs, logs, and computation keys.

A dual protection model has been implemented:
  1. Caller Responsibility Documentation & Opt-In Policy Model:
     Defines explicit guidelines detailing the responsibility of callers (build scripts,
     runners, CLI users, CI systems) when passing environment variables and arguments.
  2. Configurable Sensitive Data Policy (`SensitiveDataPolicy`):
     - `SensitiveDataPolicy::Allow`: Caller-responsible mode; no runtime checks.
     - `SensitiveDataPolicy::Warn`: Logs standard warning messages to stderr when sensitive
       keys or payload patterns are detected, without breaking the execution flow.
     - `SensitiveDataPolicy::Deny`: Strictly fails computation building/validation with
       `CacheError::SensitiveDataError` if sensitive keys or token/key values are found.
     - `SensitiveDataPolicy::Mask`: Automatically redacts secret values to `[REDACTED]` in
       environment maps and arguments during computation normalization before hashing.
  3. Comprehensive Sensitive Data Detector (`SensitiveDataDetector`):
     - Keyword detection: `PASSWORD`, `SECRET`, `TOKEN`, `API_KEY`, `AUTH`, `CREDENTIAL`,
       `PRIVATE_KEY`, `ACCESS_KEY`, `SSH_KEY`, `DATABASE_URL`, `CERTIFICATE`, `PIN`, `PASSPHRASE`.
     - Value and payload pattern matching:
       * PEM Private Keys (`-----BEGIN ... PRIVATE KEY-----`)
       * GitHub Personal Access Tokens (`ghp_...`, `gho_...`, `ghu_...`, `ghs_...`, `ghr_...`)
       * GitLab Personal Access Tokens (`glpat-...`)
       * NPM Tokens (`npm_...`)
       * Bearer / JWT Tokens (`Bearer ...`)
       * Database URIs with embedded passwords (`postgres://...`, `mysql://...`, `mongodb://...`)
