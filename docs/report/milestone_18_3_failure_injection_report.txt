1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Milestone 18.3 establishes rigorous failure injection validation across 8 realistic
operational fault scenarios, ensuring the Developer Computation Cache (`dcc`) fails
safely and predictably as robust developer infrastructure without crashing, data corruption,
or deadlock.

Simulated Fault Scenarios & Verified Safety Invariants:
  1. Disk Full / Capacity Limit:
     - Verified under strict 1 KB storage bounds with oversized multi-KB computation outputs.
     - System executes child process, records output safely, and enforces storage limits
       without panics or filesystem corruption.
  2. Permission Denied:
     - Target workspace files set to read-only (`set_readonly(true)`).
     - Engine catches OS I/O permission failures cleanly, reports structured status, and
       prevents partial or corrupt state.
  3. Process Crash:
     - Child process crashes abnormally (`exit 137`).
     - OS kernel advisory locks are automatically released, error diagnostics captured,
       and the crashed computation is excluded from cache storage.
  4. Partial Write:
     - Interrupted/abandoned staging files (`.dcc_cache/tmp/*.tmp`) are left in disk staging.
     - Uncommitted temporary files are never indexed or visible to CAS readers; subsequent
       writes succeed cleanly.
  5. Corrupted Metadata:
     - Injected malformed and truncated JSON into `.dcc_cache/entries/`.
     - Engine detects deserialization error, safely treats entry as cache miss, and repairs
       the cache record on fresh execution.
  6. Corrupted Object (Bitrot / Checksum Mismatch):
     - Injected tampered payload bytes into `.dcc_cache/objects/`.
     - On read, cryptographic SHA-256 validation detects mismatch, renames damaged object
       to `*.corrupted` (quarantine), and falls back to clean re-computation.
  7. Missing Output:
     - Command exits with code 0 but fails to generate declared required output file.
     - Post-execution validation strictly rejects caching (`CacheError::MissingOutput`).
  8. Invalid Configuration:
     - Unparseable `max_size` string, empty operation/command strings, and denied sensitive
       variables fail safely with structured `CacheError` before process execution.
