1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Milestone 7.5 addresses a critical concurrency invariant for developer tooling and
distributed caching systems: Safe Deletion. In a multi-threaded or multi-process
environment where cache eviction, manual cleaning, and garbage collection run
concurrently with active read and compute workflows, an object in active use must
NEVER be deleted underneath a reader or builder process.

Core requirements delivered:
  - "Never delete an object currently being used."
  - "Coordinate deletion with locking."
  - Shared reader locks (`ObjectLock::acquire_shared`) protecting live bitstreams.
  - Exclusive deletion locks (`ObjectLock::acquire_exclusive` / `try_acquire_exclusive`).
  - Safe, non-blocking eviction skipping (`delete_object_safe(&digest, None)`).
  - ComputationLock coordination for metadata entry removal (`delete_entry(&key)`).
  - 100% backward-compatible APIs without UI or functional regressions.

--------------------------------------------------------------------------------
2. ARCHITECTURAL DESIGN & IMPLEMENTATION
--------------------------------------------------------------------------------

1. ObjectLock Architecture (`crates/cache-storage/src/lock.rs`):
   - Reader Access: Active readers stream CAS objects under a shared lock on
     `.dcc_cache/locks/obj_<digest>.lock`. Multiple readers can concurrently hold
     shared locks on the same object.
   - Safe Deletion Coordination: Deletion routines (manual deletion, GC pruning,
     capacity-based eviction) acquire an exclusive lock on `obj_<digest>.lock`.
   - Non-Blocking Pruning (`try_acquire_exclusive`): During garbage collection
     and size eviction, `ObjectLock::try_acquire_exclusive` checks if an object is
     being read. If readers are active, pruning safely SKIPS deleting the object
     without failing or blocking the pruning operation.
   - Clean Lock Teardown: On release, exclusive deletion locks cleanly unlink the
     lockfile from disk.

2. CasStorage Safe Deletion Integration (`crates/cache-storage/src/cas.rs`):
   - `CasStorage::delete_object_safe(&self, digest: &Digest, timeout: Option<Duration>) -> Result<bool>`:
     * When `timeout` is `None` (non-blocking), skips objects in active use.
     * When `timeout` is `Some(t)`, blocks up to `t` to safely remove the object.
   - `CasStorage::delete_object(&self, digest: &Digest) -> Result<bool>`:
     * Deletes a CAS object safely with exclusive lock.
   - `CasStorage::delete_entry(&self, key: &CacheKey) -> Result<bool>`:
     * Coordinates with `ComputationLock::acquire` to protect entry metadata
       records from being deleted while a process is computing or storing results.

3. Eviction & Pruning Integration (`crates/cache-storage/src/eviction.rs`):
   - `Pruner::prune_with_options`: Traverses reachability and invokes
     `delete_object_safe(&digest, None)` to ensure any object actively locked by a
     reader is retained until the reader concludes.
   - `Pruner::evict_with_strategy`: Evicts oldest/least-frequently-used entries
     coordinating with `ComputationLock`, then triggers safe object pruning.

4. Abstract Storage Trait Compatibility (`crates/cache-storage/src/storage_trait.rs`):
   - Updated `Storage::delete` implementation for `CasStorage` to delegate to
     `delete_object(&digest)`, maintaining end-to-end safe deletion guarantees.
