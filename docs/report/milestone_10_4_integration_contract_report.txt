3. INTEGRATION CONTRACT SPECIFICATION DETAILS
--------------------------------------------------------------------------------
1. How to Declare Inputs:
   - Must be declared with relative/workspace paths, content SHA-256 digests, and file sizes.
   - Ergonomic helper `.input_path(path)` hashes and populates metadata automatically.
2. How to Declare Outputs:
   - Output paths (files or directories) created by the computation must be declared.
   - Required status is specified (`required = true/false`).
   - On cache HIT, outputs are restored atomically from CAS.
3. How to Declare Environment:
   - Only variables affecting output should be declared via `.env(k, v)` or `.declared_env(k)`.
   - Undeclared host environment variables are excluded from the canonical identity.
4. How Cache Identity Works:
   - Deterministic `CacheKey` derived from canonical JSON serialization and SHA-256 hashing.
   - Path normalization (`/`), input/env canonical key sorting ensure reproducibility across platforms and invocation order.
5. How Errors Work:
   - Validation errors (`ValidationError`, `PathTraversal`) trigger pre-execution.
   - Non-zero process exit codes do not pollute the cache by default (`FailurePolicy::DoNotCache`).
   - Corrupted CAS objects trigger quarantine and safe re-execution.
6. How Cache Misses Work:
   - Unmatched keys execute the command in the workspace directory.
   - Outputs and stdout/stderr are captured into CAS and indexed under `CacheEntry`.
   - Miss reasons can be inspected with `--explain` or `MissExplainer`.
7. How to Disable Caching:
   - Configurable at runtime via `CachePolicy`:
     * `ReadWrite` (default)
     * `ReadOnly`
     * `WriteOnly`
     * `Bypass`
     * `ForceRecompute`
