1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Milestone 6.5 subjects the Developer Computation Cache (DCC) to extreme multi-process
and multi-threaded concurrency workloads across three rigorous scales:
  - 10 concurrent processes / threads
  - 50 concurrent processes / threads
  - 100 concurrent operations executed simultaneously

The objective is to stress-test the complete storage, locking, execution, and artifact
restoration subsystems under heavy contention, validating the 4 core concurrency invariants:
  1. No storage, blob, or file corruption.
  2. No deadlocks or orphaned process hangs.
  3. No inconsistent or malformed metadata.
  4. No lost, truncated, or misplaced outputs.

--------------------------------------------------------------------------------
2. STRESS TEST SUITE & VALIDATION SCENARIOS
--------------------------------------------------------------------------------

All stress tests are implemented in `crates/cache-runner/tests/concurrency_tests.rs`:

1. Scale 1: 10 Concurrent Processes (`test_milestone_6_5_stress_10_concurrent_processes`)
   - Architecture: 10 concurrent workers synchronized with a thread `Barrier`.
   - Workload: 5 workers racing for a shared cluster key + 5 workers computing unique tasks.
   - Verified Results:
     * 0 deadlocks, 0 lock timeouts.
     * Shared cluster yielded exactly 1 MISS and 4 HITS (deduplicated execution).
     * 5 unique tasks yielded 5 MISSES.
     * All 10 worker workspaces received 100% intact output files.
     * Temporary directory `.cache/tmp/` was completely clean.

2. Scale 2: 50 Concurrent Processes (`test_milestone_6_5_stress_50_concurrent_processes`)
   - Architecture: 50 concurrent workers synchronized with a thread `Barrier`.
   - Workload: 25 workers grouped across 5 shared clusters (5 workers per cluster) + 25
     workers running independent multi-artifact computations with secondary side-outputs.
   - Verified Results:
     * All 50 processes completed cleanly within timeout bounds.
     * 100% of workers verified both primary and secondary output files.
     * No file descriptor leaks or race condition sharing violations.
     * Temporary directory `.cache/tmp/` was completely clean.

3. Scale 3: 100 Concurrent Operations (`test_milestone_6_5_stress_100_concurrent_operations`)
   - Architecture: 100 concurrent worker threads synchronized with a thread `Barrier`.
   - Workload: 40 operations hitting 4 hot computation keys (10 workers each) + 60 operations
     computing distinct large 1 KB payload artifacts with captured standard streams.
   - Post-Stress Comprehensive Integrity Audit:
     * Every worker workspace validated 100% of restored result artifacts.
     * Storage audit: Every generated `CacheEntry` record was retrieved from disk, deserialized,
       and verified via `verify_identity() == Ok(())`.
     * Cryptographic audit: Every referenced CAS object in all 100 entries was verified
       against its SHA-256 digest on disk with zero checksum mismatches.
     * Temporary storage audit: Verified `.cache/tmp/` had zero leaked files.
     * Storage stats: Verified positive object count and size metrics with 0 corrupted objects.
