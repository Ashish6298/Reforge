1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Milestone 6.4 implements and validates failure recovery for computation locks,
ensuring that abnormal process terminations, kernel crashes, timeout limits,
corrupted lock metadata, or orphaned lock files never leave the cache permanently
unusable or deadlocked.

Core Invariant:
"Never leave the cache permanently unusable because one process crashed."

Failure Dimensions Handled:
  1. Crashed processes & unexpected process termination
  2. Stale / orphaned lock files left on disk
  3. Corrupted lock metadata (e.g. malformed JSON or binary junk)
  4. Lock acquisition timeouts and non-blocking retry backoff
  5. Stale lock detection and pruning (`clean_stale_locks`)

--------------------------------------------------------------------------------
2. ARCHITECTURAL DESIGN & RECOVERY MECHANISMS
--------------------------------------------------------------------------------
- Operating System-Level Lock Release on Crash:
  * File locking is backed by OS kernel locks via `fs2::FileExt::try_lock_exclusive`.
  * If a process terminates abruptly (SIGKILL, panic, unhandled exception, power loss),
    the OS kernel automatically releases all file locks associated with that process descriptor.
  * Although the lock file `.cache/locks/<key>.lock` remains on disk, the next process
    attempting to acquire `try_lock_exclusive()` succeeds immediately without being blocked.

- Self-Healing Lock Metadata:
  * When a process acquires a lock, it writes fresh, structured metadata:
    `{ pid: u32, created_at: DateTime<Utc>, key: String }`.
  * If the lock file contained corrupted data, garbage bytes, or stale metadata from
    a dead process, the acquiring process clears and overwrites it atomically (`set_len(0)` + write).

- Configurable Lock Timeout & Backoff:
  * `ComputationLock::acquire` executes with a timeout limit (`lock_timeout`).
  * If lock contention persists beyond the timeout, it returns a descriptive error
    `CacheError::LockError` rather than hanging indefinitely.

- Stale Lock Pruning (`ComputationLock::clean_stale_locks`):
  * Scans `.cache/locks/` for locks older than a configurable `max_age`.
  * Tests each candidate with `try_lock_exclusive()`. If the lock can be acquired,
    it confirms no live process is holding it, unlocks, and safely purges the file.
