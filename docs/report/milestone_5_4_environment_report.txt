1. OBJECTIVE & REQUIREMENTS
--------------------------------------------------------------------------------
The objective of Milestone 5.4 is to support explicit declared environment variables
and prevent accidental cache fragmentation caused by undeclared system environment
variables:

    CACHE_ENV / Declared Variables:
        NODE_ENV
        GENERATOR_VERSION
        FEATURE_MODE

Core Guarantees & Invariants:
1. No Automatic Full-Environment Hashing: Unrelated process environment variables
   (e.g. `USER`, `PWD`, `SSH_AUTH_SOCK`, `TERM`, `RANDOM_TOKEN`) must never pollute
   or fragment computation keys.
2. Declared Environment Sensitivity: If a declared environment variable changes value
   (e.g. `FEATURE_MODE=legacy` vs `FEATURE_MODE=modern`), DCC derives distinct
   canonical cache keys.
3. Canonical Map Sorting: Declared environment key-value pairs are stored in a
   `BTreeMap` and serialized in alphabetical order, making key derivation invariant
   to the declaration/insertion sequence.
4. Builder Support:
   - `CommandSpecBuilder::env(key, val)`
   - `CommandSpecBuilder::envs([(k1, v1), ...])`
   - `CommandSpecBuilder::declared_env(key)` (reads variable from process environment)
   - `CommandSpecBuilder::declared_envs([key1, key2, ...])`
5. Miss Explanation: When environment differences cause a cache miss, `MissExplainer`
   identifies the exact variable key and old/new values (`MissReason::EnvironmentChanged`).
