1. OBJECTIVE & SCOPE
--------------------------------------------------------------------------------
Milestone 9.1 requires implementing and thoroughly verifying quantitative hit/miss
observability metrics in DCC:
  - total requests
  - hits
  - misses
  - hit ratio
  - execution count
  - cache restore count
  - cache store count

2. ARCHITECTURE & IMPLEMENTATION
--------------------------------------------------------------------------------
1. Metrics Aggregation Engine (`crates/cache-storage/src/stats.rs`):
   - `StorageStats` records all Milestone 9.1 metrics:
     * `total_requests`: Cumulative total computation lookups (`hits + misses`).
     * `total_hits`: Cumulative cache hits (`entry.metadata.hit_count`).
     * `total_misses`: Cumulative cache misses.
     * `hit_ratio`: Ratio of hits to total requests (`total_hits / total_requests`).
     * `execution_count`: Number of spawned/executed computations.
     * `cache_restore_count`: Number of times computation outputs were restored from CAS.
     * `cache_store_count`: Number of entries committed to CAS storage.
     * `bytes_restored`: Volume of output data served from cache without recomputation.
     * `bytes_stored`: Total volume of output data written to CAS.
     * `estimated_time_saved_ms`: Execution duration saved by serving hits from cache.

2. CLI Observability Formatting (`crates/cache-cli/src/main.rs`):
   - `handle_stats(&storage, json)` displays:
     * Aligned human-readable telemetry report via `dcc stats`.
     * Structured JSON output via `dcc stats --json`.
