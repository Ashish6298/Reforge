1. OBJECTIVE & SCOPE
--------------------------------------------------------------------------------
Milestone 8.7 requires defining, implementing, enforcing, and documenting stable,
contractual process exit codes across the CLI suite:
  0 = success
  1 = computation failed / cache entry not found
  2 = invalid configuration
  3 = cache error
  4 = integrity failure
  5 = invalid arguments

2. ARCHITECTURE & IMPLEMENTATION
--------------------------------------------------------------------------------
1. Typed ExitCode Definition (`crates/cache-cli/src/cli.rs`):
   ```rust
   #[derive(Debug, Clone, Copy, PartialEq, Eq)]
   #[repr(i32)]
   pub enum ExitCode {
       Success = 0,
       ComputationFailed = 1,
       InvalidConfiguration = 2,
       CacheError = 3,
       IntegrityFailure = 4,
       InvalidArguments = 5,
   }
   ```

2. Standardized Exit Paths:
   - `0 (Success)`: Returned upon successful execution, cache hit restoration, clean
     doctor diagnostics, successful inspect, or maintenance operations.
   - `1 (ComputationFailed)`: Emitted when an executed process returns a non-zero exit code
     or when `dcc inspect <key>` queries an unknown/missing key.
   - `2 (InvalidConfiguration)`: Emitted when configuration validation or max-size parsing fails.
   - `3 (CacheError)`: Emitted on storage system I/O or filesystem access failures.
   - `4 (IntegrityFailure)`: Emitted when `dcc verify` detects corrupted CAS blobs or when
     cryptographic hashes do not match canonical computation digests.
   - `5 (InvalidArguments)`: Emitted when required CLI parameters are missing (e.g. empty command
     after `--`) or when unknown configuration keys are provided.
