1. OBJECTIVE & SCOPE
--------------------------------------------------------------------------------
Milestone 9.3 requires implementing and thoroughly verifying Explain Mode:
  `dcc run --explain`

When a cache miss occurs, DCC explains the exact root cause of the miss in an
intuitive, human-readable format:
  - Cache lookup outcome (Result: MISS)
  - Specific reason categorization (input changed, command changed, arguments changed,
    environment changed, tool identity changed, platform changed, corrupted entry, etc.)
  - Precise diff details (Changed file, Previous sha256 hash, Current sha256 hash)

2. ARCHITECTURE & IMPLEMENTATION
--------------------------------------------------------------------------------
1. Formatted Explain Output Engine (`crates/cache-core/src/entry.rs`):
   - Implemented `MissReason::format_explain(&self) -> String` producing exact structured
     output matching the Milestone 9.3 specification:
     * `InputChanged`: Displays path, previous sha256 digest, and current sha256 digest.
     * `InputAdded` / `InputRemoved`: Displays the added or missing input path.
     * `CommandChanged`: Displays old vs new executable name.
     * `ArgumentsChanged`: Displays previous vs current argument vector.
     * `EnvironmentChanged`: Displays variable name and previous vs current values.
     * `ToolChanged`: Displays tool name/version/hash differences.
     * `PlatformChanged`: Displays OS/Arch/ABI/Target differences.
     * `CorruptedCache`: Displays integrity error details.
     * `ForcedRecompute` / `NoEntryFound`: Clean reason descriptions.

2. CLI Explain Flag Support (`crates/cache-cli/src/main.rs`):
   - In `handle_run`, when `args.explain` is set, calls `reason.format_explain()` to print
     the structured explanation upon cache miss.
