1. EXECUTIVE SUMMARY & OBJECTIVE
-------------------------------------------------------------------------------
Milestone 5.5 requires that platform-sensitive computations strictly incorporate
relevant platform constraints into the computation identity and cache key,
preventing cross-platform contamination or incorrect artifact reuse.

Core Requirement:
- Platform-sensitive computations must capture meaningful platform dimensions:
  * Operating System (os)
  * CPU Architecture (arch)
  * Target Triple (target)
  * Runtime Environment (runtime)
  * Application Binary Interface (abi)
  * Compiler / Toolchain Identity (compiler)
- Machine-specific trivia (e.g., hostnames, core counts, RAM, local absolute
  filesystem paths) MUST NOT be hashed, ensuring cache reuse is maximized across
  identical target environments.
- Any change in sensitive platform dimensions must produce a distinct canonical
  computation key, invalidating stale cross-platform cache entries.

2. ARCHITECTURAL DESIGN & IMPLEMENTATION
-------------------------------------------------------------------------------
A. PlatformConstraints Model (`dcc_core::PlatformConstraints`):
   - Structured platform definition containing:
     * `os`: String (e.g., "linux", "windows", "macos")
     * `arch`: String (e.g., "x86_64", "aarch64", "arm")
     * `target`: Option<String> (e.g., "x86_64-unknown-linux-gnu", "x86_64-pc-windows-msvc")
     * `runtime`: Option<String> (e.g., "node20", "python3.11", "jvm21")
     * `abi`: Option<String> (e.g., "gnu", "musl", "msvc")
     * `compiler`: Option<String> (e.g., "rustc 1.80.0", "clang 17.0.6")
   - Default initialization automatically detects host OS and Architecture
     (`std::env::consts::OS`, `std::env::consts::ARCH`) while keeping fine-grained
     dimensions optional to avoid accidental over-constraint.
   - Fluent builder methods provided:
     * `PlatformConstraints::new(os, arch)`
     * `with_target(target)`
     * `with_runtime(runtime)`
     * `with_abi(abi)`
     * `with_compiler(compiler)`

B. Canonical Representation (`dcc_core::CanonicalPlatform`):
   - Canonicalized in `CanonicalComputation` during SHA-256 computation key calculation:
     `{"os": ..., "arch": ..., "target": ..., "runtime": ..., "abi": ..., "compiler": ...}`
   - Included in the cryptographic digest of the computation.

C. CommandSpec Integration (`dcc_runner::CommandSpec` & `CommandSpecBuilder`):
   - Added `platform` field to `CommandSpec` and fluent helper methods to `CommandSpecBuilder`:
     * `.platform(PlatformConstraints)`
     * `.platform_target("x86_64-unknown-linux-musl")`
     * `.platform_runtime("node20")`
     * `.platform_abi("musl")`
   - Seamlessly converts into `Computation` during execution preparation.
