1. OBJECTIVE & REQUIREMENTS SUMMARY
--------------------------------------------------------------------------------
Milestone 14.3 mandates strict handling and defense against Symlink Attacks:
- A cached entry must not be able to cause arbitrary file overwrite through a malicious symlink.
- Restorations must never follow symlinks outside the workspace boundary to write, overwrite, or truncate external files.
- Restorations through symlinked directory trees that escape the workspace root must be actively detected and rejected.
- Pre-existing symlinks at destination output paths inside the workspace must be replaced rather than followed into external targets.

2. ARCHITECTURAL IMPLEMENTATION
--------------------------------------------------------------------------------
Symlink attack defenses operate across three coordinated security layers:

Layer 1: Intermediate Directory Symlink Validation (`crates/cache-core/src/paths.rs`)
- `PathUtils::verify_symlink_safety(base_dir, relative_sub)`:
  * Iterates across each path component along the relative output path.
  * Checks filesystem `symlink_metadata` for every intermediate directory and folder component.
  * If a symlink is detected on an intermediate segment or directory node, it resolves the canonical path (`canonicalize()`).
  * If the resolved canonical destination does not strictly start with the canonical workspace root (`base_canonical`), the operation immediately fails with `DccError::PathTraversal`.

Layer 2: Safe Pre-Cleaning Before Atomic Rename (`crates/cache-core/src/paths.rs`)
- `PathUtils::safe_prepare_target_path(target_path)`:
  * Uses `std::fs::symlink_metadata` to inspect whether the target path is already an existing symlink.
  * If the target is a symlink, it removes the symlink entry directly (`fs::remove_file` or `fs::remove_dir`), ensuring the subsequent atomic rename (`fs::rename`) replaces the link node rather than following the symlink into an arbitrary external file.
  * If the target is a regular file, it cleans it up safely before atomic placement.

Layer 3: Restoration Engine Integration (`crates/cache-storage` & `crates/cache-runner`)
- `Cache::restore_with_options` and `OutputRestorer::restore_entry`:
  * Validate all declared output paths using `PathUtils::sanitize_relative_path`, which invokes `verify_symlink_safety`.
  * Protect the atomic replacement phase using `PathUtils::safe_prepare_target_path`.
  * Ensure any extraction through staged temporary files `.tmp_restore_<nonce>` remains isolated.
