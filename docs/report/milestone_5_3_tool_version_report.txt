1. OBJECTIVE & REQUIREMENTS
--------------------------------------------------------------------------------
The objective of Milestone 5.3 is to define and enforce a tool identity mechanism
such that computations using different tool/compiler versions or binaries do not
silently reuse results from each other:

    compiler 1.80  ──►  CacheKey A
    compiler 1.81  ──►  CacheKey B  (Key A != Key B)

Guarantees & Invariants:
1. Tool Version Sensitivity: Modifying tool version (e.g. rustc 1.80 vs 1.81)
   strictly alters the canonical computation key.
2. Executable Digest Sensitivity: Replacing or upgrading a tool binary on disk
   (different SHA-256 digest) alters key identity even if the reported string matches.
3. Tool Identity Architecture:
   - Tool Name: Canonical identifier (e.g. "rustc", "gcc", "clang", "protoc").
   - Tool Version: Semantic version string (e.g. "1.80.0", "13.2.0").
   - Tool Binary Digest: SHA-256 cryptographic digest of the executable file.
4. Miss Explanation: When tool versions differ, `MissExplainer` pinpoints the change
   via `MissReason::ToolChanged { reason }`.
