1. OBJECTIVE & SCOPE
--------------------------------------------------------------------------------
Milestone 8.3 requires implementing and thoroughly verifying the core CLI command:
  `dcc run`

Example Concept:
  dcc run \
    --input src/schema.json \
    --output generated/client.rs \
    -- generator src/schema.json

Required Behavior Lifecycle:
  1. calculate key
  2. → lookup
  3. → HIT: restore
  4. → MISS: execute
  5. → validate
  6. → store

2. ARCHITECTURE & LIFECYCLE IMPLEMENTATION
--------------------------------------------------------------------------------
The execution pipeline is coordinated between `crates/cache-cli/src/main.rs` and
`crates/cache-runner/src/engine.rs`:

1. Calculate Key:
   - Evaluates declared input paths and hashes file contents via streaming SHA-256.
   - Combines canonical command, argument vectors, sorted environment variables,
     tool executable digest, and platform target triple.
   - Constructs a canonical `CacheKey`.

2. Lookup:
   - Queries `CasStorage::get_entry(&key)`.

3. Cache HIT Lifecycle:
   - Verifies identity match and entry integrity.
   - Restores declared output manifest items from CAS into destination paths via
     `OutputRestorer` (temporary atomic staging with rename).
   - Replays captured stdout/stderr streams.
   - Sets status to `ExecutionStatus::Hit`, `execution_time_ms = 0`, exit_code = 0.
   - Avoids executing the external command entirely.

4. Cache MISS Lifecycle:
   - Acquires lock for computation if concurrency control enabled.
   - Spawns target process in working directory, capturing stdout, stderr, and exit code.
   - If exit code == 0:
     a. Validate: Verifies all declared output paths exist.
     b. Store: Ingests each output artifact into CAS (deduplicated SHA-256 blob).
     c. Records stdout & stderr blobs into CAS.
     d. Writes canonical `CacheEntry` JSON atomically via temporary file and rename.
   - Returns `ExecutionResult` with status `ExecutionStatus::Miss`.

3. CLI ARGUMENTS & FLAGS (`RunArgs`)
--------------------------------------------------------------------------------
- `--input <path>` / `-i`: Declared input files (repeatable).
- `--output <path>` / `-o`: Declared output files (repeatable).
- `--env <KEY=VAL|KEY>` / `-e`: Declared environment variables (repeatable).
- `--op <name>`: Operation identifier (default: "default").
- `--policy <policy>`: Cache policy (read-write, read-only, write-only, bypass, force-recompute).
- `--explain`: Flag to print detailed miss reasons.
- `-- <command...>`: Command and arguments to execute.
