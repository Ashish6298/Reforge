1. EXECUTIVE SUMMARY & OBJECTIVE
-------------------------------------------------------------------------------
Milestone 5.6 requires implementing explainable, structured cache misses across the
Developer Computation Cache (DCC) system.

Cache misses must never be mysterious black boxes. When a computation does not hit
the cache, DCC pinpointedly explains why the cache was missed (e.g. no prior entry,
which input file mutated, command arguments added/removed, tool identity changed,
declared environment variable changed, platform dimension changed, or cached output
failed integrity verification).

2. ARCHITECTURAL DESIGN & IMPLEMENTATION
-------------------------------------------------------------------------------
A. Structured Miss Reasons (`dcc_core::MissReason`):
   Enum capturing precise miss semantics:
   - `MissReason::NoEntryFound`: "No previous cache entry found for this computation key"
   - `MissReason::InputChanged { path, old_digest, new_digest }`: "Input file changed: <path> (was <old>, now <new>)"
   - `MissReason::InputAdded { path }`: "New input file declared: <path>"
   - `MissReason::InputRemoved { path }`: "Previous input file missing: <path>"
   - `MissReason::CommandChanged { old, new }`: "Command changed from '<old>' to '<new>'"
   - `MissReason::ArgumentsChanged { old, new }`: "Arguments changed from <old> to <new>"
   - `MissReason::EnvironmentChanged { key, old, new }`: "Environment variable '<key>' changed from <old> to <new>"
   - `MissReason::ToolChanged { reason }`: "Tool identity changed: <reason>" (e.g., version, digest, or tool name diffs)
   - `MissReason::PlatformChanged { reason }`: "Platform changed: <reason>" (e.g., OS, arch, target triple, runtime, ABI diffs)
   - `MissReason::CorruptedCache { reason }`: "Corrupted cache entry: <reason>" (e.g., failed CAS digest / integrity verification)
   - `MissReason::ForcedRecompute`: "Forced recompute requested by policy"

B. Miss Explainer Engine (`dcc_runner::MissExplainer`):
   - Compares the active `Computation` against prior computation metadata.
   - Computes detailed diffs for:
     * Command executable and ordered argument changes
     * Input maps (hashing, added files, removed files)
     * Declared environment variable state
     * Composite tool identity (name, version, digest)
     * Platform constraint dimensions (OS, arch, target, runtime, ABI, compiler)
   - Returns structured `MissReason` with human-readable string formatting.

C. Execution Engine & CLI Integration:
   - `RunnerEngine` records `miss_reason` in `ExecutionResult`.
   - `dcc run --explain` surfaces the structured miss reason directly to developer console
     and JSON output streams.
