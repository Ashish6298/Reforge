1. OBJECTIVE & REQUIREMENTS
--------------------------------------------------------------------------------
The objective of Milestone 5.2 is to guarantee that any modification in command
executable, command arguments, argument ordering, or argument presence creates
strictly distinct canonical cache keys:

    generator --fast  ──►  CacheKey A
    generator --safe  ──►  CacheKey B  (Key A != Key B)

Invariants:
1. Argument Mutations: Changing flags (e.g. `--fast` vs `--safe`) alters key identity.
2. Argument Ordering: Arguments are semantically meaningful in CLI tools; changing
   order (e.g. `["--opt", "--debug"]` vs `["--debug", "--opt"]`) produces distinct keys.
3. Argument Additions / Removals: Adding or removing options produces distinct keys.
4. Executable Mutations: Changing the target executable binary / name produces distinct keys.
5. Isolation & Re-execution: `generator --fast` and `generator --safe` store and restore
   independent results without cross-contamination.
6. Miss Explanation: When arguments or command changes occur, `MissExplainer` yields
   `MissReason::ArgumentsChanged` or `MissReason::CommandChanged`.

2. IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
- Canonical Computation Key Derivation (`CanonicalComputation`):
  * `command` string preserves executable name.
  * `args` `Vec<String>` preserves exact ordered CLI parameter sequence.
  * Hashed via SHA-256 into 64-character hex `CacheKey`.

- Runner & Miss Explainer:
  * Detects when argument lists differ and reports `MissReason::ArgumentsChanged { old, new }`.
  * Detects when executable differs and reports `MissReason::CommandChanged { old, new }`.
