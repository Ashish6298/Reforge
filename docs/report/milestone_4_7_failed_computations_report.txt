1. OBJECTIVE & REQUIREMENTS
--------------------------------------------------------------------------------
The objective of Milestone 4.7 is to enforce the core safety guarantee that
failed computations are NOT cached by default:

    exit code != 0  ──►  DO NOT STORE

Requirements:
1. When a child process exits with a non-zero exit code:
   - No output files or partial artifacts are stored in Content-Addressed Storage.
   - No metadata `CacheEntry` record is committed to disk.
   - The execution result is returned immediately with `ExecutionStatus::Miss`,
     the non-zero exit code, execution time, and captured stdout/stderr.
2. Subsequent invocations with the identical computation specification will not
   hit cache and will re-execute the command (remains a MISS).
3. Support a future extensible policy configuration (`FailurePolicy`) while
   keeping the default v1 behavior strictly conservative (`FailurePolicy::DoNotCache`).

2. IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
- Policy Configuration:
  * Defined `FailurePolicy` enum:
    - `DoNotCache` (Default): Never store outputs or metadata for non-zero exit codes.
    - `CacheIfExplicit`: Extensibility hook for future selective error caching.
  * Added `failure_policy` field to `EngineOptions`.

- RunnerEngine Enforcement:
  * In `RunnerEngine::run_and_store`:
    - After process execution, checks `proc_output.exit_code != 0`.
    - If non-zero and `failure_policy == FailurePolicy::DoNotCache`:
      * Storage ingestion (CAS blobs and `CacheEntry` JSON) is completely skipped.
      * Returns `ExecutionResult { key, status: ExecutionStatus::Miss, exit_code, execution_time_ms, stdout, stderr, outputs: Vec::new(), miss_reason }`.
