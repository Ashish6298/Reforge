1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Milestone 8 establishes a professional, polished Command-Line Interface (`dcc`)
for the Developer Computation Cache engine. A production-grade developer tooling
CLI must provide an ergonomic, intuitive user experience for engineers while
delivering deterministic machine-readable output (`--json`) and standardized,
documented exit codes for automation, CI/CD pipelines, and script integration.

Core commands delivered:
  - `dcc init`: Local cache directory discovery, creation, and configuration.
  - `dcc run`: Sandboxed computation execution with input/output caching.
  - `dcc inspect <key>`: Deep inspection of computation manifests, timing, and CAS hashes.
  - `dcc stats`: Real-time storage telemetry, object counts, and byte footprints.
  - `dcc verify`: Complete cryptographic verification of stored CAS blobs and JSON entries.
  - `dcc clean`: Full cache wiping or single computation key removal.
  - `dcc prune`: Garbage collection of unreferenced objects and multi-policy size eviction.
  - `dcc config`: Inspection of active configuration limits and directory paths.
  - `dcc doctor`: Environment, permissions, and storage diagnostic health check.

2. ARCHITECTURAL DESIGN & IMPLEMENTATION
--------------------------------------------------------------------------------

1. CLI Command Grammar (`crates/cache-cli/src/cli.rs`):
   - Global Arguments: `--cache-dir <path>` for overriding storage roots and `--json` for machine-readable output.
   - Comprehensive Command Set:
     * `Init { max_size: Option<String> }`
     * `Run(RunArgs)`: `--input`, `--output`, `--env`, `--op`, `--explain`, `--policy`, `-- <cmd...>`
     * `Inspect { key: String }`
     * `Stats`
     * `Verify`
     * `Clean { key: Option<String> }`
     * `Prune { max_size: Option<String>, strategy: String, dry_run: bool }`
     * `Config { get: Option<String> }`
     * `Doctor`
     * `Cache { command: CacheCommands }` (for grouped maintenance subcommands)

2. Handler Implementation & Formatting (`crates/cache-cli/src/main.rs`):
   - Every handler supports dual rendering:
     * Human-Readable: Structured, formatted terminal output with aligned key-value pairs and human-readable byte sizes (e.g. `2.00 GB`, `500.00 MB`).
     * JSON Output (`--json`): Pure, pretty-printed JSON payloads ideal for `jq` and CI ingestion.
   - `handle_config`: Supports inspecting full configuration or querying specific keys (`--get max_size`, `--get cache_dir`).
   - `handle_init`: Initializes directory hierarchy (`objects/`, `entries/`, `locks/`, `tmp/`), validates storage writability, and configures default max size limit.

3. Documented & Stable Exit Codes:
   - `0`: Success / Cache HIT
   - `1`: Computation execution failed / Cache entry not found
   - `2`: Invalid configuration
   - `3`: Cache storage or I/O error
   - `4`: Cryptographic integrity check failure / corrupted object detected
   - `5`: Invalid CLI arguments or unrecognized option
