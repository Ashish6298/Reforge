1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Milestone 8.2 delivers complete implementation and verification of the `dcc init`
subcommand for the Developer Computation Cache (DCC). A robust cache environment
initialization must guarantee that:
  - Default cache directories are determined deterministically (`DCC_CACHE_DIR` -> `USERPROFILE`/`HOME` -> `.dcc_cache`).
  - All required subdirectories are created (`objects/`, `entries/`, `locks/`, `tmp/`).
  - Cache configuration (`config.json`) is persistently written to disk.
  - Storage is dynamically probed and validated for writability and access permissions.
  - A clean, structured configuration summary is emitted in both human-readable format and JSON (`--json`).

--------------------------------------------------------------------------------
2. ARCHITECTURAL DESIGN & IMPLEMENTATION
--------------------------------------------------------------------------------

1. Directory Resolution & Creation (`crates/cache-cli/src/main.rs`):
   - Path resolution checks `cli.cache_dir`, environment variable `DCC_CACHE_DIR`,
     or standard user home roots (`~/.dcc_cache`).
   - `storage.init_dirs()` automatically creates the full sharded hierarchy:
     * `objects/`: Content-Addressed Storage blobs
     * `entries/`: Immutable computation metadata JSON records
     * `locks/`: Concurrency locks for computations and CAS objects
     * `tmp/`: Atomic staging directory for write-flush-fsync-rename pipeline

2. Active Storage Validation Probe:
   - Performs a non-destructive write and removal probe in `tmp/` (`.probe_<pid>`)
     to verify disk writability before confirming initialization.
   - Provides clear, actionable error context if directory creation or write probe fails.

3. Configuration Persistence:
   - Saves `.dcc_cache/config.json` containing:
     * `version`: "1.0.0"
     * `cache_dir`: Absolute path to storage root
     * `max_size_bytes`: Configured capacity limit (e.g. `10737418240`)
     * `max_size_human`: Human-readable size format (e.g. `"10.00 GB"`, `"2.00 GB"`)

4. Summary Output Formatting:
   - Human-Readable:
     ```text
     DCC cache initialized at: C:\Users\user\.dcc_cache
     Max Cache Size: 2.00 GB
     Configuration:  C:\Users\user\.dcc_cache\config.json
     Objects:        C:\Users\user\.dcc_cache\objects
     Entries:        C:\Users\user\.dcc_cache\entries
     Locks:          C:\Users\user\.dcc_cache\locks
     Temporary:      C:\Users\user\.dcc_cache\tmp
     Storage Status: Valid & Writable
     ```
   - JSON Output (`--json`): Emits structured JSON with `status`, `cache_dir`, `max_size_bytes`, `storage_valid`, and directory paths.
