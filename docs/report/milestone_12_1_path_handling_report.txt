1. OBJECTIVE & SPECIFICATION
--------------------------------------------------------------------------------
Milestone 12.1 requires pure, cross-platform path handling across Windows,
Linux, and macOS from a single codebase.

Core Requirements:
  - Never hardcode platform-specific separator assumptions ('/' or '\').
  - Never assume platform-specific root structures ('C:\' or '/').
  - Use standard Rust path abstractions (`std::path::Path`, `PathBuf`, `Component`).
  - Ensure canonical computation key hashes are deterministic and invariant
    across operating systems regardless of slash directions (`src/main.rs` vs `src\main.rs`).
  - Sanitize and encapsulate relative paths within workspace roots, rejecting
    directory traversal attacks (`../`, `..\`, `/../`) and drive-prefix escapes.

--------------------------------------------------------------------------------
2. IMPLEMENTATION SUMMARY
--------------------------------------------------------------------------------
Added `PathUtils` in `crates/cache-core/src/paths.rs` providing:
  - `PathUtils::to_normalized_string<P: AsRef<Path>>(path: P) -> String`:
      Normalizes native OS paths into canonical forward-slash strings stripping
      redundant leading `./` components.
  - `PathUtils::to_native_path(normalized: &str) -> PathBuf`:
      Converts normalized path strings back into OS-native `PathBuf` structures.
  - `PathUtils::sanitize_relative_path<P: AsRef<Path>>(base_dir: P, rel_path: &str) -> Result<PathBuf>`:
      Safely resolves and encapsulates paths within a root workspace directory,
      preventing path escapes, absolute roots, and directory traversal.
  - `PathUtils::validate_computation_path(path_str: &str) -> Result<()>`:
      Validates declared computation paths and build action targets.
  - `PathUtils::canonicalize_for_key(path_str: &str) -> String`:
      Guarantees exact identity invariance for computation keys across Windows, Linux, and macOS.
