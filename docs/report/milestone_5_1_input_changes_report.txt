1. OBJECTIVE & INVARIANTS
--------------------------------------------------------------------------------
The objective of Milestone 5.1 is to guarantee cache correctness and deterministic
invalidation whenever declared input files change:

    If input A has hash X ──► produces Key 1
    If input A changes to hash Y ──► MUST produce Key 2 (Key 1 != Key 2)

Core Guarantees:
1. Single and multi-file input content modifications immediately alter the canonical
   computation key.
2. Changes in nested subpaths (e.g. `src/deep/nested/file.rs`) propagate to key identity.
3. Renaming input paths with identical content bytes produces distinct keys (path identity matters).
4. Input declarations are canonically sorted, ensuring declaration order invariance.
5. Invalidation triggers a clean cache miss, executes the command, records updated outputs,
   and provides a structured explanation via `MissReason::InputChanged`.

2. IMPLEMENTATION DETAILS
--------------------------------------------------------------------------------
- Canonical Computation Key Derivation (`CanonicalComputation`):
  * Normalized relative paths (`/` standard separator).
  * Inputs sorted alphabetically by path.
  * SHA-256 digests of all declared input files are embedded in canonical JSON.
  * Hashing the canonical JSON yields the 64-character hex `CacheKey`.

- Miss Explainer (`MissExplainer`):
  * Compares current input digests against prior computation manifests.
  * Pinpoints exact input paths and digest differences:
    `MissReason::InputChanged { path, old_digest, new_digest }`.
