# Getting Started with Developer Computation Cache (`dcc`)

This guide walks you through installing `dcc`, understanding its core concepts, and caching your first computation in under 5 minutes.

---

## 1. Installation

### From Source (Rust Toolchain)

Ensure you have Rust (1.75+ or stable) installed. Clone the repository and build or install the `dcc` binary:

```bash
# Clone the repository
git clone https://github.com/Ashish6298/Reforge.git dcc
cd dcc

# Build optimized release binary
cargo build --release --bin dcc

# Or install directly to your Cargo binary path ($HOME/.cargo/bin)
cargo install --path crates/cache-cli
```

Verify that `dcc` is available:

```bash
dcc --version
```

## 2. Core Concepts in 3 Minutes

DCC is a **process-level, content-addressed computation cache**. It caches the output files and standard output/error produced by any command based on its exact cryptographic inputs.

```text
Inputs (files + args + env + tool) ──► Canonical SHA-256 Key ──► CAS Lookup
                                                                      │
                   ┌──────────────────────────────────────────────────┤
                   ▼                                                  ▼
             [Cache HIT]                                        [Cache MISS]
    Restore files from CAS (0ms)                         Execute command directly
    Replay stdout / stderr                               Capture & validate outputs
    Exit code 0                                          Commit blobs to CAS & record entry
```

- **Inputs**: Files read by the command. DCC hashes their byte content (SHA-256), ignoring irrelevant file timestamps (`mtime`).
- **Outputs**: Files or directories generated by the command. On cache hit, DCC restores these files atomically to your workspace.
- **CacheKey**: A canonical SHA-256 digest derived from command args, input file hashes, declared environment variables, and tool identity.
- **Content-Addressed Storage (CAS)**: Immutable storage partitioned into 256 shards in `.dcc_cache/objects/` where objects are named by their SHA-256 hash.

## 3. Your First Cached Computation

### Step 1: Initialize the Local Cache

Run `dcc init` in your project root or workspace:

```bash
dcc init --max-size "5 GB"
```

This creates the `.dcc_cache/` directory hierarchy with partitioned storage directories (`objects/`, `entries/`, `tmp/`, `locks/`) and local configuration.

### Step 2: Create a Mock Input File

Let's create a sample schema file to simulate a code generator:

```bash
mkdir -p src generated
echo '{"user_id": 42, "username": "alice", "role": "admin"}' > src/schema.json
```

### Step 3: Run with `dcc` (Cold Run — Cache MISS)

Execute your generator command under `dcc run`. Declare the input file (`--input`) and expected output file (`--output`):

```bash
# On Linux / macOS:
dcc run --input src/schema.json --output generated/models.rs -- \
  sh -c 'echo "// Auto-generated from schema" > generated/models.rs && echo "struct User { id: u64 }" >> generated/models.rs && echo "Generated models successfully."'

# On Windows (PowerShell / CMD):
dcc run --input src/schema.json --output generated/models.rs -- \
  powershell -Command "Set-Content -Path generated/models.rs -Value '// Auto-generated from schema'; Add-Content -Path generated/models.rs -Value 'struct User { id: u64 }'; Write-Output 'Generated models successfully.'"
```

**Output:**
```text
[DCC] MISS: No existing cache entry found for key 4a9f...
[DCC] Executing command: powershell ...
Generated models successfully.
[DCC] Stored 1 output artifact(s) (58 bytes) into CAS in 4 ms.
```

### Step 4: Delete the Output File & Run Again (Warm Run — Cache HIT)

Now delete the generated file to test restoration:

```bash
rm generated/models.rs
```

Run the exact same command again:

```bash
dcc run --input src/schema.json --output generated/models.rs -- \
  powershell -Command "Set-Content -Path generated/models.rs -Value '// Auto-generated from schema'; Add-Content -Path generated/models.rs -Value 'struct User { id: u64 }'; Write-Output 'Generated models successfully.'"
```

**Output:**
```text
[DCC] HIT (key: 4a9f...)
Generated models successfully.
[DCC] Restored 1 artifact(s) in 0 ms (Execution skipped).
```

Verify that `generated/models.rs` has been restored with exact byte fidelity:

```bash
cat generated/models.rs
```

## 4. Explaining Cache Misses (`--explain`)

Whenever you wonder why a computation re-executed instead of using the cache, add `--explain`:

```bash
# Modify input file
echo '{"user_id": 43, "username": "bob"}' > src/schema.json

# Run with --explain
dcc run --explain --input src/schema.json --output generated/models.rs -- generator src/schema.json
```

**Diagnostic Output:**
```text
Cache lookup: MISS
Reason: input changed
  src/schema.json
    Previous digest: sha256:7b1a...
    Current digest:  sha256:9f3c...
```

## 5. Inspecting & Managing the Cache

### View Cache Storage Statistics

```bash
dcc stats
```

Output:
```text
DCC Cache Statistics:
  Entries:             1
  CAS Objects:         2
  Disk Usage:          1.4 KB / 5.0 GB limit
  Total Requests:      2
  Cache Hits:          1 (50.0%)
  Cache Misses:        1
  Estimated Time Saved: 142 ms
```

### Inspect a Specific Computation Entry

```bash
dcc inspect <key>
```

### Verify Integrity

Check that no cached objects have suffered bitrot or tampering:

```bash
dcc verify
```

### Run Environment Diagnostics

```bash
dcc doctor
```
